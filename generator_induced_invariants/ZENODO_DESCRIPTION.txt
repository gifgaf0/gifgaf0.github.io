A public-key construction that builds its public object by applying a fixed family of linear maps to random seeds—to compress the key, to inherit a symmetry, or to support a reduction—produces an object that is the image of a single fixed design matrix. Whatever the seeds, the rows of the public object then lie in the row space of that matrix, so its rank can never exceed the matrix's. When the rank ρ of the design matrix is below the ambient dimension, every public key is rank-deficient: exact linear algebra distinguishes it from the uniform matrix a security reduction assumes, and recovering the noise reduces to an LWE instance of dimension at most ρ. The argument takes one line—the rank of a product is at most the rank of either factor—yet the weakness is easy to miss: a rank check on a realized instance of dimension n can certify only ρ ≥ n, so a check run below the ceiling returns a clean result on a broken scheme. We make this concrete with a reproducible case study, a withdrawn sedenion Module-LWE proposal whose public matrix has rank at most 76 at every module rank and whose own structural check, run at module rank 4, could not see the ceiling. We package the lesson as an exact and cheap diagnostic—count, then compute the rank of the design matrix over the working field at the deployed size, and confirm it on an instance larger than the ceiling—with a dependency-free implementation that reproduces the case study, checks the design against the scheme's own realizations, and passes structured controls, one of them shaped like ML-KEM, and we place the mechanism among published breaks in which structure introduced for a benefit became the attack surface. Passing the diagnostic is necessary for any security argument that assumes a uniform, full-rank matrix, but not sufficient, and it costs less than the lattice estimate it should precede.
The case study is the author's own withdrawn proposal; its full break is in the author's negative-result note, doi:10.5281/zenodo.23270248.
Accompanying file: design_matrix_rank.py, the diagnostic the note describes (Python 3.8 or later, no dependencies; SHA-256 24a0d4c6a40453301fc9ba7119b2d69a211dbbd67d317b0eb422e4e8ba54e876). Running python3 design_matrix_rank.py --self-test reproduces the columns k ≤ 8 of the case study's rank table and its rank-76 ceiling, re-derives the other facts the note computes, and checks the tool's verdicts on the case study, on structured controls that pass, on designs built to fail, and on inputs it must reject.
